# OCR & EPUB 数字化常见踩坑指南 (Troubleshooting Guide)

数字化书籍转写全流程中，以下 5 个高发故障模式曾导致多次排版翻车，必须通过自动化机制与严格规范予以预防：

---

## 1. Pandoc 全局脚注冲突陷阱 (Global Footnote Collision)
- **现象**：Pandoc 在将多个 Markdown 章节同时编译进同一本 EPUB 时，默认将所有的脚注 `[^1]`、`[^2]` 视为**全局命名空间**。如果各章节都从 1 重新起号，后编译章节的同名注释会覆盖前章，导致整本书的脚注链接指向全部错位乱串。
- **解决方案**：
  在章节组装阶段（`chapter_assembler.py`），为每个章节的脚注引用与定义强制注入章节唯一前缀（例如 `[^c01_1]`、`[^c02_1]`），而视觉渲染依然保持各章独立的 1, 2, 3... 优雅连续序号。

---

## 2. 列表语法“缺少空行”导致横向坍塌 (Unspaced List Collapse)
- **现象**：
  在 Markdown 中如果写出：
  ```markdown
  **登场人物**：
  - **富姬**，天守夫人...
  - **龟姬**，来自...
  ```
  Pandoc 和 CommonMark 解析器会判定 `-` 只是上一段落的“懒惰折行（Lazy Continuation）”，导致整个列表失效，所有的列表项被全部压平成一整坨带有 `-` 符号的长句。
- **解决方案**：
  标题或引导句后**必须留有一个完整空行**：
  ```markdown
  **登场人物**：

  - **富姬**，天守夫人...
  - **龟姬**，来自...
  ```

---

## 3. 软换行（双空格）导致对白挤塞与首行缩进断层
- **现象**：
  OCR 转写时如果在台词行末使用行尾双空格软换行（`  \n`）：
  ```markdown
  **角色A**：你好。  
  **角色B**：你也好。  
  ```
  在编译为 EPUB 时，所有人的对话都会被封锁在同一个 `<p>` 标签内，仅用 `<br />` 换行。这导致：
  - 只有首位角色按 `<p>` 规则缩进 2 字符，后续所有人全部顶格 0 缩进；
  - 人物台词之间间距为 0，挤塞在一起，而遇到舞台动作时又突然拉开巨大间距，视觉极其难看。
- **解决方案**：
  每句台词必须是独立自然段（`\n\n` 分隔），行尾严禁出现双空格。由 CSS 控制 `p.dialogue` 的 `margin-bottom: 0.45em`，保证舒适的呼吸感。

---

## 4. 跨页断字与未闭合星号（Unclosed Asterisk across Seams）
- **现象**：
  在物理切分分片时，若切分点恰好落在斜体舞台动作 `*...*` 或黑体 `**...**` 内部，可能导致前一分片尾部未闭合、后一分片头部缺少开符号。这会导致 Pandoc 将接下来整整几页文字全部误判为斜体或粗体。
- **解决方案**：
  1. 切分 PDF 时优先选择自然篇目边界或空白页；
  2. 运行 `seam_auditor.py` 自动扫描分片首尾未配对的 `*` 或 `**`。

---

## 5. EPUB 后处理误伤 `nav.xhtml`
- **现象**：
  某些后处理脚本在清洗 EPUB 内的 XHTML 时，若使用粗暴的全文正则或页面清空逻辑，可能会错误清空或重写 `nav.xhtml`（EPUB 的核心目录导航），导致电子书阅读器解析目录树失败或打不开。
- **解决方案**：
  在后处理遍历文件时，必须显式排除导航文件：
  ```python
  if name.endswith(('.xhtml', '.html')) and not name.endswith('nav.xhtml'):
      ...
  ```

---

## 6. 切片局部索引导致图片同名覆盖 (Slice-Local Index Image Collision)
- **现象**：
  若在切片提取图片时直接使用切片内局部页码 `p_idx` 命名（如 `fig_p001_01`），会导致每个分片的第 1 页图片都命名为 `fig_p001_01.jpeg`，磁盘上的后分片图片直接覆盖前分片图片，且 Pandoc 编译时会将全书不同位置的插图去重合并为同一张图，造成严重错位与丢失。
- **解决方案**：
  提取图片时必须绑定全书绝对页码 `global_pno = p['start_page'] + p_idx`，强制命名为 `fig_p{global_pno+1:03d}_{img_counter:02d}.ext`，确保全局绝对唯一。

---

## 7. 随文括号注误转脚注导致跨章悬空 (Inline Note Footnote Dislocation)
- **现象**：
  原书中直接附在段落末尾的括号注（如“（注：……”）若被子智能体擅自转换为 `[^n]` 脚注，并放置在切片末尾，在后续按章节聚合时，正文角标可能属于上一章，而注释定义被切到了下一章，导致 EPUB 阅读器解析不到目标注释，点击后弹出 `(注释文本缺失)`。
- **解决方案**：
  提示词模板严格立规：原书正文中的括号注、随文夹注必须 100% 原样保留在段落内，严禁抽离为跳转脚注；仅版心底部有真实编号印制的底注才允许转为 `[^n]`。

---

## 8. 机械切片映射导致的“第XX章”假章节名 (Slice Chunk vs Semantic Heading)
- **现象**：
  若汇编器按分片编号 `part_01` $\to$ “第01章”进行分组，会生成完全违背原书目结构的虚假章节名。
- **解决方案**：
  汇编器先将所有 `raw_md` 顺序拼接为连续文本流，严格以正文中真实出现的 `## 章节标题` 作为切分边界，动态生成真实的逻辑章节文件。

---

## 9. 跨切片对白与断句接缝治理 (Cross-Slice Dialogue & Sentence Seam Healing)
- **现象**：
  物理切片分割容易切断跨页长自然段、未完结对白或无标点延续句。若机械换行，EPUB 会产生突兀空行与缩进断层；若盲目判断行尾句号，当对白句内含终结符但双引号未闭合时（如前一切片末尾为 `他说：“明天见。`，后一切片开头为 `”然后他头也不回地走了。`），粗暴规则会误判该段已完结而拒绝拼接，造成引号割裂。
- **解决方案**：
  流水线由 `seam_auditor.py` 与 `digitize_book.py` 协同执行出版级接缝仲裁：
  1. **跨切片引号闭环焊接 (`MERGE`)**：探测引号奇偶差值（前切片末行 `“` 多于 `”` 且后切片首行以 `”` 开头），自动跨分片焊合成同一自然段。
  2. **跨切片未完结断句缝合 (`MERGE`)**：探测末尾非终结标点（逗号、顿号、破折号或无标点），自动与后切片自然段连接。
  3. **文本重叠去重 (`MERGE_DEDUP`)**：探测切片重叠字句（如转写重叠），自动剔除重复前缀再平滑拼接。
  4. **可解释审计门禁**：生成 `seam_report.md`，输出全局接口决策表（含尾句/首句对照与处理动作），供快速回溯复核。

## 10. 电子书非线性图表强转表格/Mermaid 坍塌陷阱 (Infographic Table/Mermaid Collapse in EPUB)
- **现象**：
  许多数字化任务试图将研报或白皮书中的环形饼图、柱状对比图或双栏宽表强行逆向为 Mermaid 代码块或 Markdown 文本表格。在移动端或主流 EPUB 阅读器（如 Apple Books、微信读书、Kindle）中：
  - **Mermaid 裸代码暴露**：阅读器出于安全与沙箱限制，绝不执行外部 Mermaid.js 脚本，Mermaid 语法直接退化为未渲染的文本乱码；
  - **表格窄屏挤死**：手机与阅读器宽度通常仅 360~600px，多列表格被强行压缩，表头与单元格发生文字纵向换行（如“美元）名义 GDP 占比”垂直折叠），版面彻底崩坏。
- **解决方案**：
  坚持**“文字走数字流，图表走矢量流”**的双轨出版哲学：
  1. **禁止强行转写**：子 Agent 严禁将带图示或宽表的内容逆向为 Markdown 表格或裸 Mermaid；
  2. **300 DPI 无损矢量裁切**：使用 `<!-- FIGURE: page=... bbox=[...] -->` 标定坐标，由后端脚本调用 PyMuPDF 直接从原版 PDF 抽取 300 DPI 纯白底超清图片（`fig_...png`）；
  3. **自适应居中与双击放大**：在 EPUB 与 Obsidian 中以原生图片呈现，既完全保留原书专业设计配色与排版美感，又天然支持移动端自适应居中和手势全屏无级放大。
  4. **紧凑锁边与防吞并正文铁律 (Tight Bounding Rule)**：
     - 裁切图表时**严禁盲目回退到页脚底线**。对于页面上半部只有单张图表的页面，必须以图题为顶部起点（$y_0$），并以数据说明（“注：”、“数据来源”、“数据截至”）为结束点；
     - **正文绝对阻断**：若图表下方紧跟下一个正文自然段落或小节标题，遵循图文正交互斥律，底部界限 $y_1$ 紧致截断在图像主体底部，正文文本区域严格排除在 bbox 之外，杜绝将正文文字吞入图片导致 EPUB 中出现图文重复排版。

## 11. EPUB 3 数学公式离线渲染陷阱 (Offline MathML vs Client-Side JS)
- **现象**：
  若直接将包含 LaTeX 数学公式（`$...$` 或 `$$...$$`）的 Markdown 编译为 EPUB 3，许多读者在微信读书、Apple Books、KOReader 或墨水屏设备上阅读时，发现公式全部显示为原始代码（如 `<span class="math display">$$P(A|B) = \frac{P(A)P(B|A)}{P(B)}$$</span>` 或 `$$...$$` 源码字符串）。
- **根因分析**：
  1. **阅读器沙箱封锁 JS**：EPUB 3 阅读器出于安全、耗电与排版渲染稳定性考虑，默认禁用或不执行任何外挂客户端 JavaScript 脚本（如 MathJax、KaTeX）；
  2. **缺少 `--mathml` 离线转译参数**：若未在 Pandoc 编译指令中显式声明 `--mathml`，Pandoc 默认仅将公式包裹在 `span.math` 中，期待外部 JS 引擎渲染，导致公式裸露。
- **解决方案**：
  1. **编译期预转译 (Offline MathML Baking)**：
     在 Pandoc 命令中强制加入 `--mathml` 参数。Pandoc 内置的数学解析器在编译期直接将所有 TeX 数学公式解析为 W3C 标准 MathML（即 `<math display="block">` 与 `<math display="inline">`），并自动保留 `<annotation encoding="application/x-tex">` 语义备份。
  2. **阅读器全平台原生兼容**：
     几乎所有主流 EPUB 3 阅读器均原生支持 MathML 核心渲染集，无需任何外挂 JS，秒开即览，且天然支持夜间模式文字变色与字体矢量级自由缩放。
  3. **块级公式前后空行准则**：
     子智能体在转写 Markdown 时，独立块级公式 `$$` 的**上方和下方必须留有一个空行**。CommonMark 解析器与 Obsidian 要求块级结构与段落之间必须空行隔离，否则会被误判为普通内联行，导致公式排版溢出或解析混乱。

## 12. Markdown 诗歌与题记软换行坍塌陷阱 (Poetry / Epigraph Soft-Break Collapse)
- **现象**：
  原书中明明是 4 行/2 行排版的抒情诗歌或卷首题记短句，数字化转写到 Markdown 时虽按行断开，但在 EPUB 编译后却被折叠成了一整段 `<p>` 连续长句，并且在原本换行的中文字符之间被插入了半角空格（如“普遍认为 世上到底”），在阅读器中彻底丢失了诗歌分行韵律与版面呼吸感。
- **根因分析**：
  在 CommonMark 与 Pandoc 规范中，段落内部的单个换行默认视为“软换行（Soft Break）”。编译为 HTML 时，软换行会被解析为单个空格并平铺在同一个 `<p>` 标签中。
- **解决方案**：
  1. **行末反斜杠硬换行铁律**：凡题记、现代诗、古体诗、歌词或分行短句，**每行行末必须加反斜杠 `\`**。Pandoc 会精准将其转译为无多余空格的 `<br />`；
  2. **汇编器自动兜底引擎**：`chapter_assembler.py` 内置 `preserve_poetic_line_breaks`，自动嗅探题记章节与多行短句段落，自动补全行末 `\`；
  3. **Gate 3.5 编译质检**：编译后自动扫描 XHTML 中的题记与诗歌章节，校验是否存在未注入 `<br />` 的连笔长段落。

## 13. 坐标契约脱节导致文字误截为插图陷阱 (Coordinate System Contract Mismatch)
- **现象**：
  在同一页面上半部为正文文字、下半部为插图（如《推背图》第三十九象）时，生成的插图居然变成了页面上方被放大畸变的正文文字切片（如“中国……是唐代天”），插图彻底错位。
- **批判性根因复盘**：
  这**不是**子 Agent 发生视觉幻觉把文字误当成了图片（子 Agent 实际利用 OpenCV 精准识别了插图的外框，算出了正确的 PDF 点坐标 `ymin=260, xmin=97, ymax=403, xmax=196`）；
  **真实根因是上游 Prompt 与下游汇编脚本之间的接口契约断裂（Points vs Permille Mismatch）**：
  1. Prompt 模具此前仅标注 `bbox=[ymin, xmin, ymax, xmax]`，未指明单位，导致子 Agent 输出的是绝对点阵坐标（PDF Points）；
  2. 汇编脚本 `chapter_assembler.py` 内部单方面假定 `bbox` 是 0~1000 千分比归一化坐标，对输入的数值直接除以 1000 再乘页面高宽；
  3. 260 pt 被除以 1000 变成了 0.26，再乘 505 pt 页面高度，变成了 131 pt！原本处于页面下半部分的插图被强行缩小并映射到了页面顶部的正文区域，导致精准裁切到了“中国……是唐代天”的文字！
- **彻底根治方案**：
  1. **正向契约明确化（Positive SSOT）**：废除“严禁误截文字”等无用负向禁令，在所有 Prompt 模具中正面定义千分比归一化坐标计算公式：`round(coord / dim * 1000)`；
  2. **消费端自适应契约适配器 (`resolve_bbox_to_points`)**：汇编脚本增加鲁棒防御层，自动识别坐标是绝对点阵（Points）还是千分比（0~1000），消除因单位误解导致的二次缩放漂移；
  3. **切图单轨化责任制**：明确由汇编器单轨裁切，子 Agent 仅标记 Markdown 锚点，配合 `--force-recrop` 确保修整时即时覆盖。

## 14. 书名方括号清洗正则对中文定语词的误杀 (Square Bracket Noise Whitelist)
- **现象**：
  形如 `读库生鲜【2401】一只[生蚝]请求添加你为好友.pdf` 的书名，经自动化脚本清洗后，书名中的核心词汇 `[生蚝]` 惨遭剔除，变成了 `一只请求添加你为好友`。
- **根因分析**：
  传统清洗脚本使用了贪婪正则 `re.sub(r'\[.*?\]', '', base)`，将所有方括号无差别视作网盘/发布组噪音（如 `[epub]`、`[z-lib]`）。
- **解决方案**：
  严格限定噪音白名单模式：`re.sub(r'\[(?:z-library|1lib|z-lib|epub|pdf|mobi|azw3|txt)\]', '', base, flags=re.I)`，保护中文方括号词汇完整性。

## 15. 子智能体角色越界与过度思考陷阱 (Subagent Role Drift & Overthinking Loop)
- **现象**：
  子智能体在收到分片后，没有专注于本分片的视觉转写，而是越权执行 Python 脚本探测文本层、读取全书 `slice_plan.json`、研读 `SKILL.md` 与汇编器源码、甚至因担心大章标题交界而轮询等待前序分片，导致严重延迟与死锁倾向。
- **批判性根因复盘**：
  依据《writing-for-agents》的**视界封锁法则（Context Isolation）与正向导向法则（Prompt the Positive）**：
  1. 跨上下文边界（派发 Subagent）时，若未明确封锁视界，子 Agent 会被父任务的全局复杂性分散注意力；
  2. 缺乏清晰闭环动作链，导致 Agent 试图自行承担“全书宏观对齐”职责，破坏了流水线的无状态分片假设。
- **彻底根治方案**：
  1. **无状态直通铁律（Stateless Straight-Through）**：在 Prompt 首部以正向动作链锚定闭环：`view_file 加载分片 -> 逐页逐字视觉映射 -> write_to_file 落盘 -> send_message 单行汇报`；
  2. **下游仲裁责任制**：明确向子 Agent 声明跨分片标题重叠与断句缝合 100% 由下游 `chapter_assembler` 自动仲裁，严禁跨片打探与依赖。

## 16. 模型安全过滤器对医学通识史的误报熔断 (Safety Filter False Positives on Popular Science)
- **现象**：
  在处理生物医学、传染病疫苗史等社科通识读物时（如讲述海拉细胞商业化、脊髓灰质炎疫苗研发、HIV 与病毒专一性），Gemini 等模型的安全过滤器（尤其是 CBRN 生物安全模型）被触发，提示 `This request was blocked by filters ... biology-related queries` 并强制终止输出。
- **批判性根因复盘**：
  子 Agent 在阅读图片后，往往在思维链（`thinking`）中习惯性对页面上的病毒繁殖机制、细胞培养细节进行归纳与分析。安全分类器扫描到带有病毒名称和培养操作的提炼文本，误判为“指导病原体培养与生物危险操作”，从而产生误报熔断。
- **彻底根治方案**：
  1. **正向历史档案锚定（Safe Archival Framing）**：在 Prompt 中明确定义任务语境为“公开发行国家正规出版物历史文献的出版级电子化转录（Archival Transcription）”；
  2. **思维链文字直通映射（Thinking Direct-Mapping Rule）**：要求模型在思维链中仅聚焦版面拓扑与中文字符校验，严禁总结归纳生物学实验机制或病原机理，看完直接调用 `write_to_file` 直通落盘，从源头杜绝误报触发词的聚集。

## 17. 否定句诅咒与工具越权反噬 (Negation Trap & Tool Privileges Overflow)
- **现象**：
  在 Prompt 中虽然明确写了“严禁运行 Python 脚本、严禁生成删除临时图片”，但子智能体在遇到排版生僻字时，注意力被“Python脚本”、“临时图片”概念强烈激活，竟然现场写 Python 脚本裁切图片 `crop_p4_line14.png`，甚至试图通过 pip 安装 pytesseract；更有子 Agent 为了满足汇报格式中的 `{字数}字` 要求，将整段正文塞入 `python -c "text='''...'''"` 中跑脚本计数，直接触发 Windows 控制台编码崩溃；另有子 Agent 担心下游排版而用 `view_file` 跨界研读全局 `SKILL.md`。
- **批判性根因复盘**：
  依据《writing-for-agents》法则：
  1. **否定句诅咒 (Negation Trap)**：*“Don't think of an elephant, and the elephant is all there is.”* 否定词是极其微弱的修饰符，被强烈激活的概念（Python、图片、脚本）会直接盖过否定意图，导致禁令反而成了次生行为的引诱催化剂。
  2. **过度要求 (Demand Overrun)**：在完成汇报中索要 `{字数}`，诱使模型调用命令行工具去精确计算，引发不必要的次生工具调用。
  3. **上下文边界泄露**：子 Agent 继承了父级的环境甚至获知了下游 Pandoc/TOC 等宏观信息，产生不属于本职的全局焦虑。
- **彻底根治方案**：
  1. **绝对正向声明 (Zero Negation)**：模具与 Prompt 彻底删除所有“严禁/切勿/不得”，仅用四步正向动作链规范行为（打开 -> 映射 -> 落盘 -> 标记）；
  2. **裁剪完成判据**：完成判据仅保留 `[DONE] {part_name}`，彻底废除字数统计要求；
  3. **单向视界隔离**：不向子任务透露任何全书宏观管线，建立严密的单向断火墙。

## 18. 短句断行与段落缩进冲突导致的“阶梯状锯齿缩进”与三态语义模型 (The Sawtooth Indent Glitch & Tri-State Semantic Model)
- **现象**：
  在书籍数字化过程中，子 Agent 观察到纸质书版面较窄的篇首作者小传、题注、引言或边栏短语时，常误将其当作诗歌，在每行末尾机械添加反斜杠 `\`。编译为 EPUB 后，Markdown 的多行被解析为同一个 `<p>` 标签并由 `<br />` 分隔。在中文排版默认的 `p { text-indent: 2em; }` 影响下：
  - **首行**：正常缩进 2em；
  - **第二行及后续行**：因 `<br />` 强行折行导致缩进为 0；
  - **视觉灾难**：形成第一行突兀内缩、后续行顶格贴边的“锯齿状/阶梯状错位”，严重破坏出版级版面质感。
- **通用根因剖析**：
  1. **上游视觉分类模糊**：纸质出版物的狭窄分栏、人物小传与文前题注在视觉上呈短行排布，若提示词笼统强调“具有分行意图即加 `\`”，模型会将所有非满行文本误判为诗体；
  2. **下游 CSS 契约冲突**：裸 `<p>` 标签在继承中文标准 2em 缩进时，与段内 `<br />` 硬折行天然冲突。
- **彻底根治方案（全书通用三态语义模型）**：
  在 Skill 提示词与下游汇编器中，建立普适性的**文本语义三态判定模型 (Tri-State Semantic Model)**：
  1. **态 1：流式正文态（Continuous Prose - 绝对默认态）**：
     - 适用：全书故事叙述、杂文故事、人物传记长文、背景简介、科普论述；
     - 规则：段落内所有文字必须平滑缝合为连续自然段，严禁添加 `\`。段落由阅读器自适应流动排版，自然享有出版级 2em 首行缩进。
  2. **态 2：全篇诗体态（Artistic Verse - 独立篇章态）**：
     - 适用：全书开篇的独立《题记》、《序诗》、《献词》等诗歌章节；
     - 规则：必须使用显式一级标题 `# 题记`（或 `# 序诗`）。诗句行末添加 `\`（空行分节）。下游汇编器自动赋予 `epigraph-section` 样式，正文版面隐藏 H1，全诗统一样式（楷体、行距 2.15、左边距 18%、无首行缩进），保持目录清晰。
  3. **态 3：附属卡片态（Component Box / Epigraph Card - 独立小传与引文卡片）**：
     - 适用：紧随篇章标题或作者手绘头像之后的简短作者生平、引言边栏、格言短评；
     - 规则：若需保持精巧的分行版式，**严禁使用裸 `<p>` 加 `\`**，必须包裹在语义化容器中（`<div class="author-bio">` 或 `<div class="epigraph">`）；
     - CSS 防御：在 `styles_book.css` 中为容器强制配置：
       `text-indent: 0 !important; text-align: left !important; font-family: "KaiTi", serif; border-left: 3px solid #cbd5e0; background-color: rgba(0,0,0,0.02); padding: 1.1em 1.4em; line-height: 1.95;`
       彻底消除缩进错位，呈现精致雅致的现代出版卡片效果。

## 19. 有序列表与参考文献被软折行拼接压缩陷阱 (Ordered List / Bibliography Flattening Trap)
- **现象**：
  书籍末尾的参考文献或带编号清单（如 `1. 《西风》... \n 2. 《自传》...`）在 EPUB 中被压平成整坨单一长段落，导致前一项的年份与后一项的序号直接粘连（如 `19972. 陈衡哲`、`20063. 黄振翔`、`20107. 魏珂`）。
- **根因分析**：
  汇编器在执行“流式正文段落内软换行平滑缝合”时，代码仅将以 `#`、`>`、`-`、`*` 开头的块识别为特殊结构，**遗漏了以数字编号开头的有序列表（`\d+\.` / `\d+\)`）与中文序号（`一、` / `（一）`）**。当紧凑列表项之间没有空行时，分块器将其误当成普通的散文折行段落，执行了 `"".join(clean_lines)`，将所有文献条目残暴拼接为单行。
- **彻底根治方案**：
  1. **结构块白名单升级**：在 `chapter_assembler.py` 的 `preserve_poetic_line_breaks` 中，加入全量列表检测正则：凡包含 `(?:\d+[\.\)]|[-*+]|[一二三四五六七八九十]+[、.]|（[一二三四五六七八九十\d]+）)` 的块，一律判定为结构化列表块，严格保留换行，禁止跨行拼接；
  2. **列表上下空行智能隔离**：在 `normalize_text_layout` 中，将空行隔离正则由单纯的 `[-*]` 扩展为覆盖有序列表 `(?:\d+[\.\)]|[-*+])`，确保 Pandoc 100% 将其编译为出版级语义化 `<ol type="1"><li>...</li></ol>` 标签。

## 20. 图题独立换行退化为正文段落与 `<figure><figcaption>` 语义保全陷阱 (Figure Caption Body-Paragraph Degradation Trap)
- **现象**：
  原书中图片下方的图题（如“‘大海’的花。”或历史照片说明），在电子书排版中丢失了居中、浅灰的图题样式，退化为带有 2em 首行缩进、两端对齐的普通正文段落，与随后的正文叙述混为一谈。
- **根因分析**：
  1. **提示词模具误导**：若提示词示范了 `![{图题}](...)\n*{说明}*` 这种换行语法，子 Agent 会在图片占位符下方另起一行书写图题；
  2. **Pandoc 编译降级**：Pandoc 仅在图片标记独占一行且方括号非空（`![图题文字](images/foo.png)`）时，将其原生解析为 HTML5 语义化 `<figure><img ... /><figcaption>图题文字</figcaption></figure>` 容器；一旦图题写在图片下方的独立行，Pandoc 将其编译为普通的独立段落 `<p>图题</p>`（或 `<p><em>图题</em></p>`）；
  3. **中文 CSS 缩进侵蚀**：在中文排版样式中，普通段落 `p` 默认配置 `text-indent: 2em; line-height: 1.85; margin-bottom: 0.8em;`，导致独立段落的图题强行继承 2em 缩进并左对齐，完全丧失图题特征。
- **彻底根治方案**：
  1. **正向语法单一真理源 (Prompt SSOT)**：全量提示词模具严格立规，有图题时一律写在方括号内：`![图题文字](images/part_xx_fig_yy.png)`；无图题时方括号留空 `![](...)`；严禁在图片下方另起段落书写独立图题；
  2. **汇编与编译双重自愈容错 (Self-Healing Fallback)**：`epub_builder.py` 部署智能语义折叠后处理：凡探测到紧随 `<img>` 后面的段落文字较短（$\le 100$ 字）且非作者小传时，自动将其与图片合并折叠为标准 `<figure><figcaption>`；
  3. **CSS 强制清零**：在 `styles_book.css` 中为 `figcaption, p.caption, .figure-caption` 强制注入 `text-indent: 0 !important; text-align: center; font-size: 0.85em; color: #718096;`。

## 21. 篇章作者署名缺失与 `<h1 class="no-author">` 假性孤立线陷阱 (Chapter Author Omission & False `no-author` Divider Trap)
- **现象**：
  在文集、期刊或多作者专著（如《读库生鲜》）中，各章本有独立作者名（如“李松蔚”、“小庄”），但在编译生成的 EPUB 中，大标题下方没有出现优雅居中的作者署名，反而出现了一条孤零零的灰色装饰横线，而真实的作者名字要么完全丢失，要么沦为正文普通段落。
- **根因分析**：
  1. **缺乏开篇结构契约**：子 Agent 在转写时，若遇到“大标题 $\to$ 作者名 $\to$ 作者肖像 $\to$ 作者简介”的复合版面，常将作者名与简介混为一谈，或将插图直接置于标题正下方；
  2. **后处理嗅探失效与降级反噬**：`epub_builder.py` 试图用正则匹配紧跟 `<h1>` 后的第一段文字。一旦标题下紧跟插图 `<p><img /></p>`，正则匹配失败，系统判定该章“无作者”，触发兜底逻辑将 `<h1>` 改写为 `<h1 class="no-author">`；CSS 规则 `h1.no-author::after` 随即在标题下方渲染一条孤立的分割横线（原意为替代作者签名分隔），造成严重版面翻车。
- **彻底根治方案**：
  1. **显式声明篇章开篇三层契约 (Chapter Header Schema)**：
     要求所有提示词模具与流水线确立标准化开篇序列：
     若大章有独立作者/译者署名，必须紧随 `## 大章标题` 显式标注：
     `<p class="chapter-author">作者名</p>`
     后续若有作者肖像或插图，按 `<!-- FIGURE -->` 紧随其后，杜绝作者信息被插图冲断；
  2. **Gate 3.5 门禁审计拦截**：在 Step 3 汇编完成后，流水线自动审计文集各章是否存在 `<p class="chapter-author">`，杜绝非预期的假性 `no-author` 漏网。
